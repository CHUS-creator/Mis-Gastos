# Preferencias de CHUS

## 📌 Configuración General

- **Idioma preferido**: Español (proporcionar traducciones de términos técnicos en inglés cuando sea relevante)
- **Herramientas**: Preferencia por **interfaces gráficas de Android Studio** (evitar comandos de consola/terminal siempre que sea posible)

## 🖥️ Entorno de Desarrollo

- **IDE**: Android Studio (versión actual: Quail 4 2026.1.4)
- **Sistema operativo**: No especificado (asumir Windows/Android Studio estándar)
- **Metodología**: Usar menús, botones y pestañas de la interfaz gráfica

## 📝 Convenciones de Código

- **Mensajes de commit**: En **español**, claros y descriptivos
- **Nombres de ramas**: Preferencia por formato `feature/nombre-de-feature` o `fix/nombre-del-bug` (en español)
- **Pull Requests**: Descripciones en español, título claro y conciso

## 🔄 Flujo de Trabajo

1. **Sincronización**: Usar botones **Fetch** y **Pull** de la pestaña Git en Android Studio
2. **Creación de ramas**: Menú Git → Branches → New Branch
3. **Commits**: Seleccionar archivos en pestaña Git → Commit con mensaje en español
4. **Push**: Botón Push en pestaña Git
5. **Pull Requests**: Crear manualmente en GitHub Web (no hay soporte en AS)
6. **Revisión**: Aprobación manual en GitHub

## ⚠️ Restricciones y Preferencias

- ✅ **Hacer**:
  - Proporcionar instrucciones paso a paso usando menús de Android Studio
  - Traducir términos técnicos al español
  - Explicar conceptos con ejemplos prácticos
  - Usar emojis y formato visual para facilitar la comprensión
  
- ❌ **Evitar**:
  - Comandos de terminal/consola (a menos que sea absolutamente necesario)
  - Términos en inglés sin traducción
  - Explicaciones demasiado técnicas sin contexto
  - Asumir conocimiento previo de herramientas de línea de comandos

## 💡 Notas Adicionales

- El usuario se siente más cómodo con interfaces gráficas
- Preferencia por soluciones visuales y prácticas
- Necesidad de confirmación visual de cada paso
- Paciencia con explicaciones detalladas
