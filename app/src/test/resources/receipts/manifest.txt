# Corpus de tickets reales (texto OCR)

# Cada ticket es un .txt con el texto extraído de un PDF real.
# Fuente: biblioteca "TICKETS" de Mistral Studio (OCR Mistral), septiembre 2026.
# El texto conserva el ruido típico del OCR sobre papel térmico.
#
# Campos del manifiesto (separador |):
#   archivo | total | fecha_esperada | comercio_esperado | num_lineas_producto
#
# - total: importe final pagado, con coma decimal
# - fecha_esperada: formato dd/MM/yyyy normalizado
# - comercio_esperado: nombre normalizado del comercio
# - num_lineas_producto: líneas de producto esperadas (-1 = no se exige)
#   Se exige 1..N líneas detectadas: el OCR degrada nombres y el parser puede
#   fusionar líneas, pero no debe inventar líneas de más.
#   bershka: el precio va en mitad de línea (columnas TSP/IMP/UD); se exige
#   el mínimo (2 camisetas), los nombres quedan degradados por el OCR.
# comercio "-" = el formato del ticket no permite deducir el comercio con las
#   heurísticas actuales (gasolineras: cabecera metrologica; farmacia: nombre
#   en mayúsculas largo). Limitaciones documentadas, no fallos del corpus.
# --- Batch 2 (junio 2026): tickets anadidos desde la biblioteca TICKETS ---
# Limitaciones documentadas del batch 2 (no fallos del corpus):
# - ekomass/mocasas: fecha mal OCR-ada ("04 06.2026", "10.06 2026"); el
#   parser ya repara estos dos formatos (ver mangledDateRegexes).
# - ferreteria: no imprime total (solo suma de lineas, precios con 3 decimales
#   que el parser no captura) y el comercio deducido es el titular, no la tienda.
# - asiagarden_2026-06-20: fecha OCR-ada ilegible ("JONES 20/04, 2020") -> "-".
# - calvinsua ("a de PEDRO") / lapausa (cabecera "AEROPUERTO DE A CORUNA") /
#   moeve (cabecera metrologica) / farmacia gregorio: comercio deducido no
#   utilizable. farmacia_ms si deduce comercio.
# - decathlon/bershka/repsol/moeve ya extraen lineas (se quita el "EUR"
#   tras el precio antes de parsear la linea).
